# miliastra-pipeline

用代码而不是鼠标，构建原神「千星奇域」关卡。

一个人在两天里做出了一个 18,415 个控件、17.8 MiB、带加载幕、祈愿系统、商店经济和 BGM 的完整关卡。这个仓库是那两天里能复用的部分：**一套从源码到 `.gil` 的构建管线，和一本把坑挖出来的笔记。**

不含任何原神美术素材，不含成品关卡。原因见 [NOTICE.md](NOTICE.md)。

---

## 为什么需要这个东西

千星奇域的官方工作流是纯手工的：在编辑器里拖控件、连节点、调参数。做十个控件没问题，做一万个就是折磨——改一个数值要重新点一遍，调一次平衡要重录一次存档，想对比两个版本的差异只能靠肉眼。

这个仓库的思路很直接：**把关卡当程序写**。

- 界面用代码生成（一个 `sprite()` 调用产出 4,686 个矩形）
- 数值集中在 `core.js`，网页端和沙箱端共用同一份，改一次两边同步
- 构建脚本从官方教学存档克隆骨架，注入控件树和 Lua，输出可直接导入的 `.gil`
- 校验在本地跑完，不用反复导入试错

代价是你得会写 JS。收益是你能在一天里迭代二十版。

## 三条结论，能省你三天

这三条都是实测出来的，不是推测。

### 1. 画质的上限是控件预算，不是加载时间

20 MiB 存档上限，留 10% 余量是 18 MiB，除以实测 1,020 字节/控件（编辑器口径）≈ **18,500 个控件**。这才是画质的本金。

我先搞错了方向：为了把进关等待压到 1.5 秒，把人物立绘从 96px 降到 64px，控件从 18,000 砍到 7,933。实机反馈是"人物变成马赛克，不可接受"。

而当时 18,000 的预算里**有一万个空着没用**。更讽刺的是，初始化早就优化到每控件 4 次 UI 桥调用，18,415 个控件也只要 2.6 秒——加载时间根本不构成约束。

> 先定画质要什么，再算时间够不够。别反过来。

### 2. 启动慢的根因几乎总是调用次数，不是控件数量

那个"5 秒蓝屏"：屏幕上只有一块 `#183438` 纯色，整整五秒什么都没出现。

原因不是渲染慢，是初始化把 11,037 个控件每个都跑了一遍 `SetAsLastSibling` 加四次布局调用——**142,908 次 UI 桥调用**。按每帧处理 128 个控件算，要走 87 帧。5.0 秒 ÷ 142,908 ≈ 35 微秒/次，和观测值完全对上。

去掉冗余调用后是 32,400 次，降 77%。这一类问题**先数调用，别先猜引擎**。

### 3. 块外扩必须按比例，固定像素会把细节吃掉

把 PNG 转成 UI 矩形时，块边界取整会留 1px 白缝，看上去是网格或斜纹。常见做法是每块外扩一点盖住它。

v0.19 用的是固定 `+0.8px`。这里有个反直觉的地方：**显示尺寸是固定的**（人物占 245 布局单位，与源图分辨率无关），所以源分辨率越高，每块在屏幕上越小，同一个 0.8 占比反而越大。

| 源分辨率 | 块在屏幕上的宽度 | 0.8 占比例 |
|---|---|---|
| 64px | ~7.7 单位 | 10%，刚好闭缝 |
| 192px | ~2.6 单位 | **31%，每块膨胀三成再重叠** |

提分辨率本来是为了加细节，结果被一个没跟着改的常数盖掉了。正确写法是按块自身尺寸取比例：

```js
const ov = Math.min(1.2, Math.max(0.3, bw * scale * 0.12));
```

**同一份代码支持多种分辨率时，所有长度单位都必须是相对的。** 混进一个绝对像素值，它只会在某一个分辨率上正确，失效时不报错，只是变糊。

## 快速开始

需要 Node 20+，以及两个外部依赖（都不在本仓库里）：

| 依赖 | 用途 | 获取 |
|---|---|---|
| `miliastra-ugc-tools` | 读写 `.gil` 二进制、构建 UI 树 | [QHY8IV/miliastra-ugc](https://github.com/QHY8IV/miliastra-ugc) |
| 官方教学存档 | 作为构建基底的骨架 | 编辑器导出，或仓库讨论区置顶 |

```bash
# 1. 把 PNG 编译成 UI 矩形描述
node src/compile-sprites.mjs ./assets

# 2. 算一下你的控件预算够不够
node src/budget.mjs --controls 18415 --bytes-per-control 1054

# 3. 构建（需要先在环境变量里指向工具目录）
MILIASTRA_TOOLS=/path/to/miliastra-ugc-tools node your-build.mjs
```

`src/budget.mjs` 是独立小工具，不依赖任何外部库，可以先跑起来感受一下预算模型。

## 一个提醒

这套东西的价值不在于"能自动生成控件"，而在于**它让你能快速试错**。

我把第 1 关到第 20 关的目标值、六档命座概率、商店五类商品的价格，全部用脚本跑过一遍模拟，才敢说"普通玩家约 10 关"这个设计目标。手工点的话，一轮平衡调整要半天，你只会调两次就放弃。

**能快速验证的方案，才会被真的验证。**
